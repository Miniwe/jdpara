# Фундамент структуры ведения проекта

Система-симбиоз трёх методологий: **Johnny.Decimal** (жёсткая адресация),
**P.A.R.A.** (динамика актуальности) и **MOC / LYT** (карты контента для
навигации). Все три усилены четвёртым слоем — правилами, которые делают
структуру предсказуемой для ИИ-агента, читающего и правящего файлы.

## 1. Johnny.Decimal — жёсткий каркас адресации

Глубокая вложенность папок одинаково плохо читается человеком и ИИ: чем
больше уровней, тем дороже понять, где лежит файл, не читая его. Johnny.Decimal
решает это числовыми префиксами: каждая категория внутри проекта получает
двузначный номер (`00-входящие`, `10-источники`, `20-вопросы`, `30-решения` и
т.д.), а не смысловое вложенное дерево.

Практический эффект: увидев префикс `20-`, и человек, и ИИ сразу знают тип
содержимого без чтения — это открытый вопрос, а не знание и не решение.
Новый файл создаётся по префиксу, а не «куда покажется логичнее».

## 2. P.A.R.A. — динамика актуальности

Метод Тиаго Форте делит информацию не по теме, а по тому, насколько она
нужна прямо сейчас:

- **Projects** — то, над чем идёт работа, у чего есть цель/горизонт.
- **Areas** — зоны постоянной ответственности без фиксированного финала.
- **Resources** — справочная база: знания, источники, процессы, шаблоны.
- **Archives** — всё завершённое или неактуальное, но не удалённое.

В этом хранилище верхний уровень — это P.A.R.A. (`(P) Проекты`,
`(R) Ресурсы`, `(A) Деятельность`/`(A) Журнал`, `(a) Архив`), а Johnny.Decimal
работает **внутри** каждого проекта или раздела ресурсов как второй слой
адресации. Один файл — один физический адрес; если он относится к двум
областям, вторая область получает вики-ссылку, а не копию.

## 3. MOC / LYT — карты контента и навигация

Внутри проекта или раздела заводятся файлы-диспетчеры, которые ничего не
хранят сами, а только собирают ссылки и живые запросы (Dataview/Tasks):
`README.md` (вход), `состояние.md` (дашборд), `план.md` (текущий горизонт),
`журнал.md` (append-only лог). ИИ и человек начинают ориентацию в теме с
карты, а не со сканирования всей папки — это резко снижает расход токенов
на каждый запрос.

## 4. Слой для ИИ-агента

Строгая адресация ценна ровно потому, что снимает для ИИ задачу «куда
класть» — она решена структурой заранее. Из этого вытекают конкретные
правила:

- **Frontmatter — паспорт файла.** Каждый файл начинается с YAML-блока.
  Ключи полей — латиницей (`status`, `приоритет` — тоже допустимо, если
  так решено для проекта), значения — по-русски (`статус: открыт`, не
  `status: open`). Единообразие ключей важнее их языка: важно, чтобы один
  и тот же проект не путал `status`/`статус` без причины. Перечень уже
  используемых значений — [[Теги, типы и статусы]].
- **Типизированные сущности несут `id`.** Вопрос — `Q-NN`, решение —
  `D-NN`, процесс — `P-NN`, эксперимент — `E-NN`. Номер сквозной внутри
  типа и не переиспользуется даже после закрытия.
- **У каждого вопроса — обязательный раздел «Что изменится от ответа».**
  Если ответ ничего не меняет — это не вопрос, файла не должно быть.
- **У каждого решения — «Основание» и «Отвергнутые варианты».** ИИ не
  принимает решения за человека: заводит их со статусом `предложено`,
  перевод в `принято` — действие человека.
- **Источники (`10-источники`) — только чтение.** Ошибка в источнике —
  факт об источнике, а не повод его исправить; она фиксируется в заметке
  знания.
- **Секрет не попадает в файл.** Ни в новый, ни в старый, ни в пример
  конфига — ни в частичном виде, ни «только имя переменной без значения»,
  если сама переменная это и есть секрет.
- **Правка блока, не файла целиком.** Модифицируя `план.md` или
  `состояние.md`, меняется конкретный раздел — остальное, включая
  комментарии человека, остаётся как было.
- **Журнал только растёт вниз.** Строки не редактируются и не удаляются;
  ошибка исправляется новой строкой, а не правкой старой.

## 5. Что получается в итоге

Johnny.Decimal даёт структуре скелет (предсказуемые адреса), P.A.R.A. —
динамику (что сейчас важно), MOC — навигацию (карты вместо сканирования),
а правила для ИИ — язык, на котором агент может читать и дополнять
хранилище без порчи существующего контента. Рабочий пример — папка
[[00 Пример зрелого проекта|_STARTER-KIT/(P) Проекты/01 Пример зрелого проекта]]
этого же комплекта.

проектов одновременно и на мультиагентные сценарии.
