# Настройка Obsidian

Снимок конфигурации текущего рабочего хранилища на 2026-09-19. Цель —
взять новый пустой Obsidian, выполнить шаги ниже и получить окружение,
которое ведёт себя так же: те же плагины, те же горячие пути, тот же
внешний вид. Это не архив `.obsidian/` (там могут быть личные пути и
кэши) — это воспроизводимая инструкция.

## 1. Community-плагины — установить и включить

Через **Настройки → Community plugins → Browse**, по одному, именно в
этом смысловом порядке (сначала инфраструктурные, потом рабочие):

| Плагин | Зачем |
|---|---|
| **Dataview** | живые запросы по frontmatter и задачам — на нём построены [[Фокус]], [[Сводка задач]] |
| **Tasks** (`obsidian-tasks-plugin`) | чекбоксы с приоритетом (🔺⏫🔼), датами `due`/`scheduled`, блоки `tasks` |
| **Kanban** (`obsidian-kanban`) | доска верхнего уровня — [[Канбан-доска]] |
| **Calendar** | навигация по дневным заметкам |
| **Iconic** | иконки папок/файлов, используется во frontmatter (`icon:`) MOC-файлов |
| **Colored Tags** | визуальное различение тегов типа `moc/inbox`, `пример` и т.п. |
| **Mermaid Tools** | помощники для диаграмм Mermaid (карты, схемы в `карта.md`) |
| **Document Exporter** | экспорт заметок |
| **Obsidian LiveSync** | синхронизация хранилища через CouchDB (см. раздел 5 — требует своей настройки, ключей здесь нет) |
| **BRAT** (`obsidian42-brat`) | установка плагинов не из официального каталога — используется для `karpathywiki` |
| **Karpathywiki** | сторонний плагин (устанавливается через BRAT) |
| **AI Audio Transcription & Summary** | расшифровка голосовых заметок в текст |
| **Copilot** (`obsidian-copilot`) | чат/ИИ-ассистент внутри Obsidian — модели и ключи настраиваются отдельно, см. раздел 6 |
| **Markdown Formatting Assistant** | вспомогательное форматирование Markdown |

Установлены, но **не включены** в текущем хранилище (можно пропустить
при первой настройке, включить по потребности): `better-export-pdf`,
`captains-log`, `perplexity-converter`, `smart-connections`,
`smart-connections-visualizer`.

## 2. Core-плагины — сверить включённые

**Настройки → Core plugins.** Отключено по умолчанию в этом хранилище
(осознанно, не забыто): `footnotes`, `slash-command`, `markdown-importer`,
`zk-prefixer`, `random-note`, `slides`, `audio-recorder`, `publish`,
`webviewer`. Всё остальное ядро — включено, в том числе `daily-notes`,
`templates`, `bases`, `sync`, `bookmarks`, `canvas`.

## 3. Общие настройки (Settings → Files & Links / Editor)

| Настройка | Значение | Где менять |
|---|---|---|
| Расположение новых файлов | `current` (в текущей папке, не в корне) | Files & Links |
| Автообновление ссылок при переносе | включено | Files & Links |
| Папка для вложений | `(R) Служебные/Assets` | Files & Links |
| Номера строк в редакторе | выключены | Editor |
| Проверка правописания | выключена | Editor |

## 4. Daily Notes и Templates

| Плагин | Настройка | Значение |
|---|---|---|
| Daily notes | папка | `(A) Журнал` |
| Daily notes | шаблон | `(R) Служебные/Шаблоны/Шаблон День.md` |
| Templates | папка шаблонов | `(R) Служебные/Шаблоны` |

Разместить сами шаблоны (`Шаблон День.md` и остальные) в
`(R) Служебные/Шаблоны` — они не входят в этот starter-kit как файлы,
только как ссылка на путь; шаблоны сущностей этого комплекта — в
[[_шаблоны]] рядом с этим файлом.

## 5. Dataview — нестандартные настройки

Большинство настроек Dataview оставлены по умолчанию, кроме:

- `dataviewJsKeyword: dataviewjs` (по умолчанию) — важно, что
  `enableDataviewJs` и `enableInlineDataviewJs` **включены** — без этого
  не заработают блоки ` ```dataviewjs ` в [[Фокус]] и [[Сводка задач]].
- `refreshInterval: 2500` — дашборды перечитываются раз в 2.5 секунды.

## 6. Внешний вид

| Настройка | Значение |
|---|---|
| Тема | AnuPpuccin (Settings → Appearance → CSS themes; установлена через Community themes) |
| Акцентный цвет | `#13d110` |
| Шрифт интерфейса | PT Sans Caption |
| Шрифт текста | PT Sans |
| Моноширинный шрифт | PT Mono |
| Базовый размер шрифта | 16 |
| Полупрозрачность окна | выключена |

Дополнительно установлены (не обязательно активная) темы **ITS Theme** и
**Obsidian Nord** — можно поставить любую, тема не влияет на структуру
хранилища.

## 7. Iconic — иконки

Ключевые переключатели: `minimalFolderIcons: true` (иконки папок в
минималистичном стиле), `showTitleIcons`/`showMarkdownTabIcons: true`
(иконка видна и в заголовке файла, и на вкладке). Сами иконки
привязываются через поле `icon:` в frontmatter MOC-файлов (см. `icon:
target` в [[Фокус]], `icon: list-checks` в [[Сводка задач]]) — их нужно
расставить руками через контекстное меню Iconic или frontmatter, плагин
их не генерирует автоматически.

## 8. Copilot — ИИ внутри Obsidian

Плагин установлен, но **ни один API-ключ в конфигурации не хранится** —
в снимке хранилища все поля `*ApiKey` пустые. Чтобы получить рабочий
чат:

1. Настройки плагина Copilot → указать ключ нужного провайдера
   (Anthropic/OpenAI/Google/OpenRouter и т.д.) самостоятельно — ключи не
   часть этого комплекта и никогда не должны в него попадать (см. раздел
   про секреты в [[00 Фундамент структуры ведения проекта]]).
2. Папка данных плагина — `(R) Служебные/copilot` (история диалогов,
   кастомные промпты в подпапке `copilot-custom-prompts`).
3. Contexts: `qaExclusions: copilot` — сам плагин не индексирует свою же
   папку с историей при построении контекста.

## 9. Obsidian LiveSync — синхронизация

Плагин установлен, но в снимке хранилища **не настроен** (адрес CouchDB,
логин и пароль — пустые строки, `liveSync: false`). Если нужна
синхронизация между устройствами — настраивается отдельно, это выходит
за рамки структуры хранилища: см. официальную документацию плагина.
Секреты синхронизации (URL/логин/пароль базы) не должны попадать ни в
один файл этого хранилища — только в настройки самого плагина
(`data.json` плагина не синхронизируется как заметка).

## 10. Что не входит в этот комплект осознанно

- Сами файлы тем/плагинов — устанавливаются через Community
  plugins/themes заново, не копируются как бинарники.
- Значения любых API-ключей, токенов, паролей CouchDB — не хранятся
  нигде в этом хранилище ни в каком виде.
- Личные пути и `userId` — специфичны для установки, не переносятся.
