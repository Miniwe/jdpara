# Теги, типы и статусы

Справочник значений, которые уже встречаются во frontmatter файлов этого
комплекта — чтобы не придумывать новый термин там, где уже есть подходящий.
Соглашение (раздел 4 в [[00 Фундамент структуры ведения проекта]]): **ключ
поля — латиницей** (`type`, `status`, `priority`, `id`), **значение —
по-русски** (`status: открыт`, не `status: open`). Русский ключ
(`приоритет`, `обновлено`) допустим, если так решено для конкретного
проекта — важно не смешивать оба варианта одного и того же поля внутри
одного проекта.

## `type` — тип файла

Отвечает на вопрос «что это за документ», независимо от того, в каком
проекте он лежит.

| Значение | Где используется | Смысл |
|---|---|---|
| `project` | README проекта | карточка проекта — вход, описание, структура |
| `readme` | README (когда без полной методологии) | то же, но без притязания на «полный профиль» |
| `правила` | `CLAUDE.md` | регламент для ИИ-агента внутри проекта |
| `дашборд` | `состояние.md` | MOC-снимок текущего состояния, живая карта |
| `план` | `план.md` | текущий горизонт, без галочек |
| `журнал` | `журнал.md` | append-only лог событий |
| `знание` | заметки в `15-знание/` и в `(R) Ресурсы` | атомарная очищенная мысль, верна независимо от конкретного проекта |
| `источник` | файлы в `10-источники/` | неизменяемый оригинал, только чтение |
| `входящее` | файлы в `00-входящие/` | сырое, неразобранное |
| `задачи` | плоский список дел (проекты без Johnny.Decimal) | чек-лист без карточек-вопросов |
| `daily` | файлы `(A) Журнал/ГГГГ-ММ-ДД.md` | дневная заметка: фокус дня, чек-листы, входящий лог |

Типизированные сущности (`Q-`, `D-`) обычно не несут `type` — их тип уже
виден по `id`, дублировать нет смысла.

## `status` / `статус` — стадия жизни документа

Набор значений зависит от типа сущности — вопрос и решение живут по
разным жизненным циклам.

**Вопрос** (`20-вопросы/Q-*.md`):

| Значение  | Смысл                                            |
| --------- | ------------------------------------------------ |
| `открыт`  | развилка ещё не разрешена                        |
| `отвечен` | ответ получен, вопрос можно закрыть              |
| `снят`    | оказался неважным — от ответа ничего не менялось |
| `протух`  | контекст исчез, вопрос больше не актуален        |

**Решение** (`30-решения/D-*.md`):

| Значение | Смысл |
|---|---|
| `предложено` | ИИ подготовил решение с основанием, человек ещё не подтвердил |
| `принято` | человек подтвердил, решение действует |
| `отменено` | решение отозвано без замены |
| `заменено` | решение отозвано, но есть новое `D-NN`, ссылающееся на него |

**Проект** (`README.md` проекта) — здесь `status` свободнее по форме: это
короткое текстовое описание текущей стадии, а не фиксированный enum
(`идёт разработка MVP`, `собираем материал`, `развивать паралельно`).
Причина: у проектов слишком разная природа (см.
[[(P) Проекты/01 Пример зрелого проекта/README|01 Пример зрелого проекта]]
против [[(P) Проекты/02 Пример простого проекта/README|02 Пример простого проекта]]),
чтобы одна и та же стадия называлась одинаково у всех. Что фиксировано —
это отдельное поле `приоритет`/`приоритет` (см. ниже), а не `status`.

## `priority` / `приоритет` — приоритет

Два независимых слоя, не путать:

**Приоритет проекта** (`приоритет` в README проекта) — редко меняется,
отвечает «что вообще в работе»:

| Значение | Смысл |
|---|---|
| `1` | в фокусе — держать 2–4 проекта одновременно ([[Фокус]]) |
| `2` | актуально, но не сейчас |
| `3` | фон — когда-нибудь |

**Приоритет вопроса** (`priority` в карточке `Q-*.md`) — отвечает «что
внутри проекта важнее всего прямо сейчас»:

| Значение | Смысл |
|---|---|
| `блокер` | без ответа нельзя двигаться по текущему плану |
| `высокий` | не блокирует, но заметно тормозит |
| `обычный` | стандартный темп разбора |
| `когда-нибудь` | интересно, но не горит |

Задачи вне карточек-вопросов (простой проект без `20-вопросы`, например
[[(P) Проекты/02 Пример простого проекта/Задачи|Задачи]]) используют
собственный слой приоритета — эмодзи плагина Tasks (`🔺` наивысший, `⏫`
высокий, `🔼` средний, без значка — обычный/низкий). Эти два механизма не
смешиваются: если у проекта есть `20-вопросы`, приоритет читается из
карточек вопросов (как в [[Фокус]]), а не из Tasks-эмодзи.

## `tags` — теги

Теги здесь вторичны по отношению к структуре папок и к типизированным
полям выше — они помогают поиску и группировке, но не заменяют `type`/
`status`. Встречающиеся значения:

| Тег | Где | Смысл |
|---|---|---|
| `moc/inbox` | корневые дашборды (`README`, `Фокус`, `Сводка задач`, `Канбан-доска`) | живой агрегатор верхнего уровня, ничего не хранит сам |
| `moc` | `состояние.md`, `план.md`, `журнал.md`, `структура.md` | карта контента внутри проекта или раздела |
| `проект` | README проектов | карточка проекта |
| `пример` | все тестовые данные этого комплекта | помечает, что содержимое демонстрационное, не реальное |
| `методология` | файлы `(R) Ресурсы` уровня «Фундамент…» | знание о самой системе, а не о предметной области проекта |
| `справочник` | этот файл | перечисление допустимых значений, а не отдельная мысль |
| `ии`, `регламент` | `CLAUDE.md` | правила для ИИ-агента |

## Как добавить новое значение

Если в проекте понадобилось значение, которого нет в этом списке —
добавить его сюда же, а не оставлять только в одном файле: справочник
теряет смысл, если отражает не все значения, которые реально встречаются
в хранилище.
